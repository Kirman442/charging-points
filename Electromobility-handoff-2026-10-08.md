Интерактивная карта зарядной инфраструктуры Германии и аналитика для электромобильности/логистики. Репозиторий: https://github.com/Kirman442/charging-points . Опубликованное приложение: https://kirman442.github.io/charging-points/ .

Стек: Vite/React (JS), deck.gl, MapLibre через @vis.gl/react-maplibre, Apache Arrow/Parquet, Web Workers, числовые индексы и TypedArrays. Python готовит данные, joins и дорожную аналитику; spatial joins не должны переноситься в браузер.

Ранее оптимизация дошла до шага 25: отложена фоновая загрузка деталей, числовые группы/индексы. Пользователь считает скорость на LTE приемлемой; дальнейшая общая оптимизация производительности сейчас не является задачей. Branch dev/main и фактический текущий git status проверить локально: этот снимок не доказывает состояние веток после поздних шагов.

Предыдущие общие числа данных: 67 680 площадок и 208 570 зарядных точек. Для BEV используется KBA FZ1.2 по Zulassungsbezirke. Не подменять уровни «площадка», «оборудование», «точка» и «разъём»; суммирование мощности оборудования отличается от суммирования разъёмов.

## Текущий приоритет: дорожная доступность автобанов

Работаем с A5, A1 и A9, в обоих направлениях. Это исследовательская дорожная модель; результаты не являются доказательством юридического соответствия AFIR.

Текущий порог мощности для интервалов: площадка ≥400 кВт суммарной мощности оборудования и хотя бы одна DC-точка ≥150 кВт. Мощность берётся из реестра/подготовленных числовых групп. Не суммировать мощности OSM-разъёмов для изменения мощности площадки, не объединять автоматически соседние площадки.

Условия пилота: автомобильный подъезд ≤3 км, возврат на своё направление ≤3 км, привязка к дороге ≤60 м. Радиус поиска кандидатов OSM — 150 м. Предыдущие промежуточные модели могли использовать другие пределы; для нынешних выводов использовать текущую политику, а не смешивать её со старыми.

Найденный путь заканчивается на проекции на дорогу, а не обязательно на зарядном месте. Геометрия маршрута не должна искусственно соединяться прямой линией через забор/парковку. Строгая привязка выбирает ближайшую дорогу (с допуском 0,5 м); если она недоступна, алгоритм не перескакивает автоматически на другую доступную дорогу. Поэтому отсутствие пути к координате и наличие к соседней зарядке может быть следствием координат/привязки, а не изменения дорожной сети.

Отдельно оценивать:

- принадлежность объекта OSM площадке реестра;
- связность дорожного подъезда и возврата;
- последние метры до зарядного места;
- фактические условия доступа: шлагбаум, ограничение для клиентов, часы работы.

Парковочный карман вдоль улицы, территория АЗС и отдельная парковка имеют разные способы въезда. Отдельный тег entrance не обязателен для каждого типа. Здание/пешеходный entrance вне автомобильного графа не является автомобильным въездом. Барьер рядом с маршрутом не равнозначен барьеру на пути. `access=permissive` не доказывает круглосуточно открытый шлагбаум; `access=customers` требует проверки условий.

A1 имеет реальный разрыв: две части, northern/southern, по два направления. Не соединять их искусственно. Названия площадок Nord/Süd не равнозначны направлению north/south автомобиля.

2. При готовности прочитать сводку и результаты А1/A9. Числа шага 30 — baseline, не прогноз новых результатов.
3. По готовому А5 сгруппировать 98 shared-сопоставлений по (osm_type, osm_id) и по множеству конкурирующих site_id; убрать повторы по направлениям. Сначала вывести число уникальных объектов/групп.
4. Сравнить принадлежность: оператор/проверенная марка, реестровые мощности и типы оборудования, ref/EVSE где доступны, адрес, отдельные территории/парковки, явные названия сторон. Дистанция сама по себе не подтверждает владельца.
5. Учитывать ситуации нескольких реестровых площадок одного оператора на одной территории и OSM-объекта целого пула. Допускать «несколько возможных соответствий»; не форсировать one-to-one и не перераспределять мощность.
6. Сохранить явные подтверждённые/отклонённые соответствия с источником и датой, отличая вывод алгоритма от внешнего подтверждения. Не стирать неоднозначность автоматически.
7. Начать ручную проверку с power-priority review_priority=0: концы длинных интервалов, затем остальные площадки ≥400 кВт/DC ≥150 кВт. Проверить последний участок въезда и условия доступа.
8. Только после обоснованной проверки влияющих площадок решать обновление дорожных связей, интервалов и карты. Текущий шаг выдаёт отчёт, не меняет браузерные данные. Публикацию и фактическую ветку сверять отдельно.

Общение на русском. Действовать по согласованной задаче без постоянных вопросов «продолжать?».
