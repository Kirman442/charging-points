# 28_step — восстановление сохранённого извлечения

Распаковать СОДЕРЖИМОЕ архива в корень charging-points, объединить scripts/tests и заменить extract_pbf_networks.py и test_pbf_extraction.py. Ничего не удалять из data_sources/pbf-work-0yy7qbnf. Зависимости уже установлены на шаге 27; устанавливать их повторно не требуется.

## Команда из корня проекта (одна строка)

```bat
.venv-pbf\Scripts\python.exe scripts\recover_pbf_networks.py --pbf "M:\projekte\Ladesaeulenregister\data\germany-latest.osm.pbf" --resume-dir "data_sources\pbf-work-0yy7qbnf" --routes A1 A9
```

Сначала проверяется objects.sqlite и создаётся отдельная objects-recovery.sqlite. Оригинальный objects.sqlite и locations.idx не изменяются и не удаляются. locations.idx вообще не открывается при восстановлении.

Далее скрипт вычисляет SHA-256 PBF и сверяет выборку сохранённых объектов с исходным PBF. Использовать именно тот неизменённый PBF, который участвовал в первом запуске. Шаг 27 не сохранял исходный SHA-256 в SQLite: выборочная сверка НЕ доказывает тождество всех исходных объектов; это ограничение отражено в отчёте. Для следующих попыток восстановления уже сохраняется SHA-256, и другой PBF будет отвергнут.

Недостающие ways и nodes извлекаются прямыми проходами по PBF с фильтрами ID, без координатного кэша и без повторного геометрического отбора всей сети. PBF всё равно читается локально; это не мгновенное восстановление. После каждой завершённой итерации сохраняется рабочая база. Затем проверяются ссылки ВСЕХ сохранённых дорожных ways и ограничений поворотов, экспортируются JSON и ZIP.

Результат:

```text
data_sources\pbf_networks\road-networks-a1-a9.zip
```

После строки Done прислать этот ZIP. До подтверждения результата оставляем старую папку pbf-work-0yy7qbnf как резервную копию. Если процесс завершится ошибкой, прислать ПОЛНЫЙ traceback: теперь ошибки очистки не скрывают исходную причину. Новые рабочие данные не удаляются. Если выходная папка уже создана после частичного экспорта, для повтора указать новую: `--output data_sources\pbf_networks_retry`. Рабочая objects-recovery.sqlite будет использована повторно.

Этот пакет также исправляет основной экстрактор: замыкание ограничений больше не использует locations.idx, исходный traceback печатается полностью, сбой сохраняет рабочую папку, ошибка удаления временных файлов после успешного экспорта становится предупреждением. Устаревший shapely.ops.transform заменён на shapely.transform.

Полная Германия и Windows здесь не тестировались. Четыре интеграционные проверки выполнены на небольшом PBF в Linux: извлечение и ссылки, сохранение разрыва A1, повреждённый PBF, сценарий сбой → сохранённая SQLite → восстановление без locations.idx. Дополнительно проверено, что исходная база не меняется и смена PBF при повторе отклоняется. Маршруты и интервалы карты этим шагом ещё не пересчитываются.

Запуск проверок:

```bat
.venv-pbf\Scripts\python.exe -m unittest discover -s tests -p test_pbf_extraction.py -v
```
