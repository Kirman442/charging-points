# 31_step — пробная проверка подъездов и признаков въезда на A5

Распаковать архив в **корень charging-points с объединением папки scripts**.
Запустить `31_step_run_a5_entry_audit.cmd` двойным щелчком либо из CMD.
Используется уже созданная `.venv-pbf`; повторно скачивать Germany PBF не нужно.

Исходный PBF:
`M:\projekte\Ladesaeulenregister\data\germany-latest.osm.pbf`

Все рабочие файлы и результаты:
`M:\projekte\Ladesaeulenregister\data\31_step_a5_entry_audit\`

Временные файлы Python/pip направлены на M:; pip запускается без кэша.
Проект, PBF и готовые браузерные Parquet не изменяются. Интервалы не пересчитываются.

## Что будет сделано

Пробный участок A5 между широтами 50.19 и 50.30, район Köppern / Friedberg —
Ober-Eschbach / Bad Homburger Kreuz. Оба направления анализируются отдельно,
с промежуточными съездами и подъездами к площадкам отдыха.

Из полного локального PBF собирается сеть вокруг этого участка с запасом 8 км.
Вместе с дорогами сохраняются ограничения поворотов, барьеры, точки зарядок,
полигоны зарядных площадок/парковок и обозначенные входы/въезды.
Площадка из реестра должна относиться к этому участку по проекции на A5;
коридор первоначальных кандидатов — 3,5 км.

Проверяется путь для легкового автомобиля: подъезд ≤3000 м, возврат ≤3000 м
на то же направление и привязка к ближайшей дороге ≤60 м. Геометрия строится
по настоящим направленным рёбрам. Расстояние привязки не превращается
в выдуманную дорогу между координатой и зарядкой.

Дополнительно ищутся объекты `amenity=charging_station` в пределах 150 м
от координаты реестра. **Это радиус поиска соответствий, а не правило допуска.**
Близкие объекты проверяются отдельно; автоматически считать их той же площадкой
нельзя. Для зарядки-полигона используется внутренняя представительная точка,
которая не является подтверждённым автомобильным въездом.

Кандидаты на въезд: пересечения разрешённых service-дорог с границей связанной
парковки/зарядной территории, а также обозначенные входы/барьеры на автомобильном
графе. Отдельный вход в здание вне автомобильной сети не принимается за въезд.
Полигоны `area=yes` не превращаются в дороги по их периметру.

Ни связь с близким объектом OSM, ни граница парковки сами по себе не подтверждают
доступ. Все такие записи имеют `association_verified=false` и
`entrance_verified=false`. Проверяется дорожная модель; фактический въезд
потребует просмотра и подтверждения. Отсутствие найденного пути не доказывает,
что на местности въезда нет.

## Ход выполнения

Полный PBF читается последовательно; первичная подготовка координат на HDD
может занимать заметное время. В консоли будут отметки времени и этапы обработки.
Кэш координат находится на M:, в `work\pbf-work-*`, а не в RAM или на C:.
Успешная экстракция освобождает свой временный каталог; при ошибке сохраняет его.
В Windows, если файл ещё удерживается ОС, результат сохраняется, а очистка
каталога откладывается.

Неполные ограничения поворотов сохраняются и блокируют связанные дороги.
Они не снимаются ради получения маршрута. Перед поиском проверяется,
что основная трасса в PBF совпадает с ранее разобранной геометрией A5.

При повторном запуске готовый локальный JSON используется снова.
Если изменились PBF или участок, программа попросит другой `--output`;
исходные файлы автоматически не удаляются. При сбое пришли текст ошибки,
особенно строку с именем сохранённого каталога.

## Что прислать после завершения

Только небольшой архив:
`M:\projekte\Ladesaeulenregister\data\31_step_a5_entry_audit\a5-entry-audit-results.zip`

Содержимое:

| Файл | Назначение |
|---|---|
| audit.json | Сводка по направлениям, параметры, источник и время |
| site-review.csv | Площадка, цель поиска, расстояния, дороги и результат |
| routes.geojson | Линии подъезда (`arrival`) и возврата (`return`) |
| sites.geojson | Исходные площадки из реестра |
| mapped_chargers.geojson | Близкие объекты зарядок OSM для проверки соответствия |
| road_terminals.geojson | Точки, где маршрут заканчивается на дороге |
| entry_candidates.geojson | Кандидаты на автомобильные въезды |
| osm_areas.geojson | Связанные парковки и зарядные территории |

GeoJSON можно открыть в QGIS как отдельные слои. В routes.geojson фильтровать
по `direction`, `site_row`, `target_kind` и `leg`; координаты — WGS84.
Для одной площадки могут быть строки обоих направлений и нескольких объектов OSM.
Пустой слой означает отсутствие соответствующих объектов в выбранной выгрузке,
а не физическое отсутствие зарядки/въезда.

Дорожный JSON и временные SQLite/locations.idx присылать не требуется.

## Запуск вручную

Из корня проекта, после установки зависимостей командным файлом:

```bat
.venv-pbf\Scripts\python.exe -u scripts\a5_entry_audit.py --pbf "M:\projekte\Ladesaeulenregister\data\germany-latest.osm.pbf" --output "M:\projekte\Ladesaeulenregister\data\31_step_a5_entry_audit"
```

Параметры `--lat-min` / `--lat-max` меняют участок. Для другой области
использовать новую папку `--output`. `--network` позволяет воспроизвести поиск
на уже имеющемся дорожном JSON; старый JSON может не содержать зарядки и парковки,
поэтому основной запуск использует PBF.

## Проверки

Проверены длины и непрерывность экспортируемых путей, отсутствие прямой линии
через привязку, запрет частного проезда, отбор пеших входов и запрет использования
периметра дорожного полигона как автомобильной дороги. Экстракция проверена
на маленьком настоящем PBF с зарядной точкой и парковкой.
Поиск также выполнен на существующей региональной дорожной сети A5.
Windows CMD проверен по содержимому; запуск на Windows здесь не выполнялся.
