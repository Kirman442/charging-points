# 32_step: проверка четырёх площадок А5 на своём компьютере

Распакуйте архив с объединением папок в `M:\projekte\Ladesaeulenregister\charging-points`.
Запустите **32_step_run_a5_identity_review.cmd** из корня проекта.

Обработка выполняется на вашем компьютере. PBF не читается заново. Используются сохранённая небольшая сеть шага 31 и файлы реестра из `public/data`. Скрипт не изменяет карту, исходные файлы, статусы площадок или интервалы.

По умолчанию предыдущий расчёт должен находиться здесь:
`M:\projekte\Ladesaeulenregister\data\31_step_a5_entry_audit`.
В нём нужны `audit.json`, `site-review.csv`, шесть GeoJSON-слоёв и `network\a5\access-network.json`. Архив результатов шага 31 без папки network недостаточен. Если папка находится в другом месте, исправьте TASK_PREVIOUS в `.cmd`, не запускайте экстракцию заново.

Результат: `M:\projekte\Ladesaeulenregister\data\32_step_a5_identity_review`.
Откройте `review.html` и пришлите **32-a5-identity-review-results.zip** из этой папки.
Все временные файлы запуска размещаются на M:. Точная продолжительность зависит от диска; это локальный разбор сохранённых файлов, а не повторный проход по Германии.

## Что проверяется

Четыре физические площадки: 29399, 29402, 34033, 34036; оба направления. Номера — индексы в конкретном срезе, поэтому скрипт проверяет SHA-256 реестра, связь таблицы адресов с координатами и источник дорожной сети. При несовпадении останавливается.

Сравниваются операторы и адреса из реестра с полными тегами объектов OSM. Один OSM-кандидат может быть связан сразу с несколькими площадками; это явно отмечается по всему участку шага 31. Различие названий компаний не доказывает различие операторов, а совпадение не подтверждает объект автоматически. Общая мощность площадки и мощность одного устройства — разные величины.

Для уже рассчитанных подъездов и возвратов проверяются узлы въездов/шлагбаумов в пределах 30 м от пути. `on_traversed_geometry=true` означает принадлежность узла использованной дороге и реально пройденной геометрии, с допуском 0,75 м; учитываются неполные крайние участки дорог. Это не подтверждение фактической доступности. Допуски проверки не меняют условия пилота 3 км / 3 км / 60 м.

В JSON сохранены полные теги дорог и относящиеся к ним ограничения поворотов, оператор, адрес, оборудование реестра и точки окончания дорожного маршрута. Геометрия не достраивается прямой линией до зарядки. Для ручного просмотра в QGIS можно открыть GeoJSON-слои. `osm-object-details.json` — подборка объектов, а не полноценная сеть для нового расчёта.

Все `association_verified` и `entrance_verified` остаются false. Автоматического подтверждения въезда и пересчёта интервалов нет. Повторный запуск обновляет только файлы результата шага 32; исходный шаг 31 сохраняется.

Ручной запуск:

```bat
.venv-pbf\Scripts\python.exe scripts\a5_identity_review.py --previous "M:\projekte\Ladesaeulenregister\data\31_step_a5_entry_audit" --output "M:\projekte\Ladesaeulenregister\data\32_step_a5_identity_review"
```
