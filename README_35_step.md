# 35_step — A5, затем A1 и A9 на вашем компьютере

Запуск 8 октября 2026 завершился в 23:12:07 без ошибок за 9937,4 с.
Готовая папка `35_step_motorway_review` — сохранённый исторический результат.
Не запускать её повторно: исправленный CLI отклоняет завершённый output до
изменения отчётов. Для нового расчёта нужен новый `--output`; сейчас он не нужен.

Распакуйте с объединением папок в M:\projekte\Ladesaeulenregister\charging-points.
Запустите 35_step_run_all_motorways.cmd. Все вычисления выполняются на вашем компьютере.

Порядок: A5 → совместное извлечение коридоров A1/A9 из локального PBF → A1 → A9.
А5 использует отчёт шага 34 и сеть шага 33: PBF и маршруты А5 повторно не пересчитываются.
Скрипт проверяет сохранённые ограничения на дорогах, сопоставления операторов,
мощности, общих кандидатов и явно противоречащие названия Nord/Süd или Ost/West.
Общие кандидаты здесь лишь помечаются для проверки; конкурирующие площадки
сравниваются отдельно по [инструкции разбора](README_36_step_shared_review.md).
Названия сторон площадки не отождествляются с направлениями движения.
123energie сопоставляется с Pfalzwerke по официальному источнику.
Несовпадения имён, отсутствующие данные, общие кандидаты и неподтверждённые
последние метры остаются предметом проверки. Въезды автоматически не подтверждаются.
Наличие барьера на пути фиксируется, а не приравнивается к запрету проезда.

Для А1 сохраняется реальный разрыв трассы: две части, по два направления.
Маршруты привязаны к известным исходным JSON; при изменении этих файлов запуск
останавливается до извлечения. Сообщение об отличии файла надо прислать для адаптации.
Дополнительно проверяется соответствие основного маршрута вашему PBF.
Пределы: подъезд и возврат по 3 км, привязка к дороге до 60 м, кандидаты OSM до 150 м.
Привязка сохраняет строгий выбор ближайшей дороги — перескакивание через ограждения
или на другую доступную дорогу автоматически не разрешается.

Извлечение A1/A9 выполняется совместно, включая дополнительные проходы при
необходимости дополнить ограничения поворотов. Прерванный первый проход надо
повторять; извлечение не имеет восстановления с середины PBF. Готовые сети и
проверенные участки по 50 км используются повторно. После ошибки одного дорожного
аудита скрипт пытается выполнить следующий. Неполная экстракция останавливает оба.
Точного времени для A1/A9 нет. Расчёт A5 раньше занял 1 ч 20 мин, но это не замер
этого пакета. Завершение A1/A9 к утру не гарантируется.

Все временные файлы, кэш pip, сети, журналы и отчёты сохраняются на M:.
Установка использует существующий .venv-pbf в корне проекта.
Нужно минимум 25 ГБ свободного места. На время работы отключите сон компьютера.
Карта, исходные таблицы, готовые Parquet и интервалы не изменяются.

A1/A9 включают геометрию. A5 содержит только новые оценки и очереди проверки;
его исходные маршруты/GeoJSON остаются в `34_step_a5_full_entry_review`.

Если выполнение остановилось раньше, пришлите конец 35-desktop-review.log.
Повторный запуск того же CMD продолжает готовые участки при неизменных входах.

Это относится к незавершённым запускам исправленной версии. Привязка участков
теперь включает orchestration, evidence, checkpoint helper и весь engine.
Старые checkpoints не перепривязываются автоматически; они сохраняются,
а несовпадение кода требует нового output.

Экстракция сначала экспортируется в `network.pending`. Завершённый экспорт
получает receipt с хэшами обеих сетей и extraction-audit, затем публикуется как
`network`. Сбой между публикацией и записью checkpoint восстанавливается по
receipt без PBF. Незавершённый экспорт без receipt сохраняется в отдельной
папке `.incomplete-*`; новый проход начинает экстракцию с начала. Неверные
хэши или другая привязка останавливают запуск, файлы не удаляются.

Очередь ручной проверки: power-priority.csv, сначала review_priority=0 —
концы десяти самых длинных известных интервалов в каждом направлении, затем
остальные площадки с нужной мощностью. Это очередь проверки, не исправленные интервалы.
Для отдельного запуска доступны --mode a5 и --mode night (через Python CLI).
