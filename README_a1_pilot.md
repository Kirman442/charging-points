# A1: пилот по направлениям и отдельным участкам

Это обновление приложения поверх A9 road-access / ветки dev шага 25. Все изменения A9 включены. Распаковать в корень проекта, затем `npm run build` и `npm run preview`. Python для просмотра карты не требуется.

В левом блоке выбрать A1, включить режим автобана и проверить оба направления. По умолчанию показывается только линия. В поле «Площадки на карте» можно включить DC ≥150 кВт с найденным маршрутом, все DC ≥150 кВт или всех кандидатов. Открытие площадки из списка показывает только выбранную точку, даже при скрытых площадках. При отдалении радиус точек уменьшается до 1 пикселя. A9 остаётся доступной для сравнения. Файлы A2–A4 пока не подключены: сначала проверяется A1.

| Направление | Кандидаты в коридоре | Дорожные связи | DC ≥150 кВт с найденной связью | ≥400 кВт и DC ≥150 кВт | Максимальный расчётный интервал, км |
|---|---:|---:|---:|---:|---:|
| К Heiligenhafen | 2062 | 547 | 173 | 109 | 55.6 |

На северном участке максимумы 41,6 км к северу и 48,6 км к югу. На южном — 55,6 и 55,8 км: по одному жёлтому интервалу на направление, красных нет. Неизвестные края маршрутов не включаются в максимумы. Площадки на границах жёлтых интервалов вынесены в `data_sources/a1/yellow-interval-review.csv` для ручной проверки.

## Геометрия

Исходный пользовательский `data.zip` содержал A1–A4, A9 и JSON A4. Для A1 восстановлены настоящие ID узлов из Geofabrik Germany со срезом 2026-10-04T20:20:21Z. GeoJSON пользователя новее (2026-10-06), поэтому расчёт целиком использует единый срез PBF, а не смешивает координаты разных дней.

Немецкая A1 — relation 9716761 (`network=BAB`), вложенные relations 5611236 и 20904. Отбор по точному `ref=A 1` пропускал общие участки A1/A61. Relations позволили восстановить их реальные геометрии. Три пограничных ways принадлежат иностранным A1 по relations NL:A и AT:A-road и исключены. 21 отсутствующий участник около Kelberg включён явно по пользовательской выгрузке и проверен по PBF. Все решения перечислены в `data_sources/a1/selection.json`.

Для основной линии исключены motorway_link и два конечных trunk-сегмента. Параллельная ветвь 101621723 с `motorcar=discouraged` не включена в основной путь; это не утверждение о запрете проезда. В Blankenheim две проезжие части соединяются в OSM через общий конечный узел 1359941472: исходный U-образный обход разделён там на два направления.

| Участок | К северу, км | К югу, км |
|---|---:|---:|
| Heiligenhafen–Blankenheim | 606,394 | 606,723 |
| Kelberg–Saarbrücken | 139,426 | 139,004 |

Официальный проект Autobahn GmbH подтверждает реальный разрыв около 25 км между Blankenheim и Kelberg: https://www.autobahn.de/planen-bauen/projekt/a1-lueckenschluss-zwischen-blankenheim-kelberg

Через этот разрыв не проведена линия и не считается зарядный интервал. Длины в панели — сумма реально выбранных участков, не длина сквозного маршрута с объездом. Километраж площадки считается отдельно от начала каждого участка в выбранном направлении; это не официальный дорожный километраж.

## Дорожные связи и интервалы

Методика та же, что для A9: подъезд от съезда ≤3 км, возврат на своё направление ≤3 км, привязка координаты к геометрически ближайшей дороге ≤60 м. Учитываются одностороннее движение, повороты, ограничения доступа и препятствия. Сложные/условные ограничения консервативно исключаются. Найденный путь к дороге рядом с площадкой не доказывает реальный въезд на её территорию.

Бирюзовые площадки — дорожная связь найдена; светлые — кандидат в коридоре поиска, но связь не найдена. «DC-площадки ≥150 кВт в коридоре» включает обе категории. Кнопка открывает карточку и приближает карту.

Интервалы вычислены внутри каждого отдельного участка между съездами к площадкам с найденным маршрутом, ≥400 кВт номинальной мощности и DC-точкой ≥150 кВт. Сплошная линия ≤50 км, длинный пунктир >50–60 км, короткий >60 км; неизвестные края — серые. Это исследовательские интервалы, не сертификация соответствия AFIR. Фильтры карты меняют отображение, а не базовые показатели маршрута.

## Подготовка

Готовые данные находятся в `public/data/autobahn_a1_zstd10.parquet`. Worker загружает A1 только по запросу, отдельно кэширует A1/A9 и проверяет название маршрута, число площадок и SHA-256 стартового файла. Числовые связи сохраняют исходные индексы площадок; исходные файлы шага 25 не менялись.

```bash
python -m pip install -r scripts/requirements-a9.txt
python scripts/prepare_a1.py
```

Повторная подготовка использует `data_sources/a1/access-links.json`, привязанный к точным файлам площадок, оборудования и геометрии. При изменении входов нужно пересчитать связи, а не переносить индексы вручную.

Полная коридорная сеть находится в архиве по пути `offline_sources/a1/access-network.json`; она не загружается браузером и исключена из git. Повторный расчёт:

```bash
python scripts/prepare_a1.py --network offline_sources/a1/access-network.json
```

## Ручная проверка

`data_sources/a1/site-review.csv` содержит площадки с адресами, участком, направлением и расстояниями. В первую очередь проверить съезды/возвраты и фактические въезды у площадок, влияющих на самые длинные интервалы. После проверки A1 можно переходить к A2.

Атрибуция: OpenStreetMap contributors, ODbL https://www.openstreetmap.org/copyright ; Geofabrik https://download.geofabrik.de/europe/germany.html . Зарядные данные проекта: BNetzA, срез 2026-09-01. Ограничения нормативной оценки описаны также в README_a9_pilot.md.

## Автоматические проверки

66 JS-тестов, 17 Python-тестов, lint и сборка прошли. Проверены привязка к площадкам, различие A1/A9, отдельные секции без соединения через разрыв, направленность дорог, ограничения доступа и устаревшие кэши.

В Chromium проверены переключение A9→A1→A9→A1, оба направления, скрытие, открытие карточек и сброс. Каждый Parquet загружен ровно один раз, ошибок JavaScript нет. Подложка тестовая; скорость рабочего хостинга не измерялась.
