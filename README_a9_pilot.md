Исторический пилот. Актуальный baseline: 302/314 связей и максимумы 42,1/42,1 км,
см. [шаг 30](README_a1a9_exit_zones.md). Таблицы ниже описывают прежний срез.
[Шаг 35](README_35_step.md) создаёт отдельную диагностику без обновления карты.

Обновление поверх пилота A9 или `dev` шага 25 (база `cc6ce5b`). Push и публикация не выполнялись.

## Установка и проверка карты

Архив содержит обновлённые файлы приложения и подготовленный Parquet. Распаковать **в корень проекта**, затем:

```bash
npm run build
npm run preview
```

Включить «Режим Автобан A9». Проверить оба направления, скрытие остальных площадок и сброс настроек. В правой панели раскрыть список DC-кандидатов: кнопка «Открыть площадку» приближает карту и открывает обычную карточку; «К аналитике» возвращает панель A9. Для просмотра Python не требуется.

## Что означают цвета

Бирюзовые площадки: найдены подъезд и возврат по дорогам. Светлые: кандидаты без найденной связи. Остальные приглушены или скрыты. **Ни один цвет площадки не подтверждает её реальный въезд.**

Интервалы считаются вдоль выбранной проезжей части между съездами к площадкам с найденной связью, суммарной номинальной мощностью ≥400 кВт и хотя бы одной DC-точкой ≥150 кВт. Рисунок линии дополняет цвет: сплошная ≤50 км, длинный пунктир >50–60 км, короткий >60 км, серый пунктир — неизвестный интервал/край маршрута. В этом срезе цветные интервалы все ≤50 км: жёлтых и красных не ожидается. В конце южного направления есть кандидат у конечного узла, поэтому отдельного серого хвоста нет.

Это предварительная инфраструктурная оценка, **не заключение о соответствии AFIR**. Адресная группа не является автоматически физическим charging pool; фактические въезды, публичная доступность, одновременная мощность, TEN-T, исключения и нормативный срок ещё не проверены. Нынешний срез не доказывает состояние на конец 2025 года. Порог 50 км — аналитическое предупреждение проекта.

Километраж отсчитывается отдельно от начала каждого направления, длина в EPSG:32632 не является официальным дорожным километражем. Базовые показатели относятся ко всему набору; фильтры карты меняют показ площадок, а не расчёт интервалов.

## Проверка подъездов в Python

`scripts/a9_access.py` использует ориентированные дорожные рёбра и проверяет переходы на поворотах, включая съезды/въезды на A9. Учтены oneway, ограничения для motorcar/motor_vehicle, круговые перекрёстки, частный/запрещённый доступ и препятствия. Применены 2 949 простых ограничений поворотов; 164 сложных/условных ограничения консервативно исключают соответствующие ways вместо игнорирования.

Пределы модели: подъезд от съезда ≤3 км, возврат на выбранное направление ≤3 км, расстояние координаты площадки до геометрически ближайшей дороги ≤60 м (допуск равных дорог 0,5 м). Более дальняя доступная дорога не подменяет ближайшую закрытую. Разрешённый маршрут к дороге около координаты **не является доказательством въезда на территорию**. Неизвестные шлагбаумы исключены; исключения и обрезка дорожного коридора могут давать пропуски.

Исходная геометрия A9: relation `20738`, шесть вложенных TMC-relations. Два реально отсутствующих участника около Hermsdorf, `725303216` и `725303217`, восстановлены явно по OSM. На разрывах не создаются прямые соединения.

## Воспроизведение

```bash
python -m pip install -r scripts/requirements-a9.txt
python scripts/prepare_a9.py
```

В архив включён компактный кэш проверенных связей `data_sources/a9/access-links.json`: числовые индексы, расстояния, съезды/въезды, OSM ways путей и аудит источника. Подготовка проверяет SHA-256 площадок, оборудования и геометрию направлений. Несовпадение требует пересчёта; кэш не переносится молча на новые данные.

Для полного повторного расчёта распаковать ранее полученный `a9-access-network.zip` рядом с проектом и указать дорожный JSON:

```bash
python scripts/prepare_a9.py --network ../a9-access-investigation/access-network.json
```

Полная сеть (~62 МБ JSON) не включена в обновление и не загружается браузером. В браузере Parquet A9 занимает 143 211 байта (около 140 КиБ), загружается только при первом включении режима и использует существующий Worker/WASM. Числовые `site_row` привязаны к SHA-256 стартового файла и его числу строк, клики сохраняют исходные индексы. Формат обновлён до `a9-pilot-v2`; данные и код нужно обновлять вместе.

Без кэша и без `--network` подготовка оставляет связи неизвестными. Чтобы обновить геометрию через OSM, доступен `fetch_a9.py`; после изменения маршрута потребуется повторная проверка сети. Большие дорожные выгрузки в git не добавлять.

## Следующая ручная проверка

В `data_sources/a9/entrance-review.csv` — 20 примеров для проверки (оба направления, разные участки и расстояния до дороги). `site-review.csv` содержит все кандидаты. Проверить фактический въезд, разворот/возврат на нужную сторону и ограничения на территории. До этого расчётные интервалы не следует выдавать за подтверждённое покрытие.

## Проверки

63 JS-теста, 14 Python-тестов, lint и сборка. Проверяются направленность, повороты, частный доступ, препятствия, ближайшая дорога, устаревший кэш, числовые индексы, пределы расстояний и интервалы. Chromium: оба направления, одна ленивая загрузка Parquet, скрытие, переход из списка в карточку, возврат и сброс; ошибок JavaScript нет. Подложка тестовая одноцветная, скорость хостинга не измерялась.

```bash
node --test tests/*.test.mjs
python -m unittest discover -s tests -p 'test_a9*.py'
npm run lint
npm run build
```
